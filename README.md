# GymPassJUST — CSP11

نسخة التسليم حسب نطاق مشروع GymPass الأصلي، الإصدار 2.0.0.

## مهم: تشغيل المشروع

1. ثبّت Node.js 24 LTS، من 24.10 وحتى آخر إصدار 24.
2. نزّل المشروع كاملًا وفك الضغط.
3. افتح **Start-GymPass.cmd** وانتظر اكتمال تثبيت المكتبات.
4. افتح http://localhost:3000 واترك نافذة التشغيل مفتوحة.
5. اضغط **الدخول بالحساب الجامعي** ثم اختر هوية تجريبية.

من الطرفية:

    npm ci --ignore-scripts
    npm start

**الدخول محاكاة OIDC للتقييم، ولا تستخدم حساب الجامعة الحقيقي. لا توجد كلمات مرور محلية ولا تخزين لكلمات المرور.**
حسابات الموقع المستضاف القديم لا تخص هذه النسخة. الموقع القديم لم يُحدّث بهذا الإصدار.

## مهم: الحسابات وطريقة التجربة

| الهوية من صفحة الدخول | استخدمها من أجل                                      |
| --------------------- | ---------------------------------------------------- |
| أحمد خالد — عضو فعال  | الباقات والحجز والانتظار والبطاقات وسجل الحضور       |
| سارة محمد — عضو فعال  | تجربة عضو ثانٍ وقائمة الانتظار                       |
| عضو بعضوية منتهية     | التحقق من رفض الحجز والبوابة قبل التجديد             |
| مدرب الحصص            | حصصه وقائمة المسجلين وتسجيل الحضور وإلغاء الحصة      |
| Front desk staff      | البوابة والبحث عن العضو وبيع عضوية ورفع إيقاف مع سبب |
| مدير المركز           | الباقات ونشر الجدول والإحصائيات والتدقيق             |

اخرج من الحساب قبل اختيار هوية أخرى. البيانات التجريبية: 1,500 عضو و12 مدربًا وموظف استقبال ومدير و60 حصة في أسبوع تجريبي.
التواريخ تُنشأ عند أول تشغيل وتبقى محفوظة في **data/csp11.db**.

## مهم: القواعد

- يفتح الحجز قبل الحصة بـ48 ساعة ويتطلب عضوية مناسبة تغطي مدتها.
- السعة ثابتة؛ عند الامتلاء ينتقل العضو لقائمة انتظار FIFO.
- الإلغاء متاح حتى ساعتين قبل البداية، ويقبل وقت الحد بالضبط.
- المقعد المحرر بسبب الإلغاء أو الغياب ينتقل تلقائيًا لأول منتظر مؤهل مع إشعار.
- **دخول البوابة مستقل عن حضور الحصة:** بطاقة Gate entry تتطلب عضوية فعالة دون حجز حصة، وموظف الاستقبال يفحصها.
- بطاقة Class attendance يفحصها المدرب المعيّن، أو يستخدم زر Check in في القائمة. يلزم حجز مؤكد.
- الرمز موقّع ويتغير كل 60 ثانية. تكرار رمز دخول البوابة نفسه مرفوض.
- بعد عشر دقائق من بداية الحصة يسجل الغياب. ثلاث حالات خلال 30 يومًا توقف الحجز سبعة أيام.
- توضيح تصميم للمنتظر المترقي بعد البداية: عشر دقائق من الترقية للحضور ضمن مدة الحصة. ليس هذا ادعاء موافقة من الدكتور.
- الاستقبال يرفع الإيقاف بسبب مكتوب، وتظهر العملية في التدقيق.
- الدفع محاكاة. التجديد يبدأ عند انتهاء نفس الباقة الحالية، ويسمح بتجديد واحد مجدول.
- دورة المهام كل دقيقة؛ قرب الحدود قد يظهر التغيير خلال دقيقة.

## تجربة عملية

1. كمدير أنشئ حصة مستقبلية بسعة 1 ومدرب 1 دون تعارض.
2. احجز كعضو أول، ثم كعضو ثانٍ ليظهر الانتظار.
3. ألغِ حجز الأول قبل البداية بساعتين؛ الثاني يترقى مع إشعار.
4. افتح بطاقة العضو وانسخ Gate entry؛ كاستقبال الصقه في البوابة قبل نهاية الدقيقة. تكراره يرفض.
5. عند بدء الحصة يسجل مدربها حضور العضو المؤكد خلال أول عشر دقائق.
6. راجع الإحصائيات والتدقيق كمدير.

الاختبارات تستخدم ساعة متحكمًا بها؛ لا تحتاج انتظار أيام لفحص الغياب والإيقاف.

## الاستضافة وOIDC خارجي

HTTP المحلي على loopback مخصص للتقييم. NFR-03 يتطلب HTTPS للاستضافة. جهّز TLS لدى الوكيل واضبط NODE_ENV=production وAPP_ORIGIN=https://YOUR_HOST وOIDC_ISSUER=https://YOUR_TEST_PROVIDER وOIDC_CLIENT_ID وOIDC_CLIENT_SECRET عند الحاجة وSIGNING_SECRET عشوائيًا بطول32 حرفًا على الأقل.
سجّل APP_ORIGIN/auth/callback لدى مزود الهوية، مع RS256 وemail_verified=true.
الأعضاء الجدد يدخلون عبر OIDC كأعضاء. بعد دخول الموظف أول مرة يحدد المشغّل دوره:

    node scripts/provision-role.js staff@example.edu desk

الأدوار: member / instructor / desk / manager. الأمر للمشغّل وينهي جلسات الحساب ويسجل التغيير.
النشر الخارجي واختبار مزود خارجي غير مكتملين. لا تعتبر الرابط القديم دليلًا لهذه النسخة.
